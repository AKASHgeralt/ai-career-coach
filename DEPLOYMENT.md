# Deployment

Deploys the app on free tiers, at no cost, with no card required.

| Piece | Host | Free tier | Why this one |
|---|---|---|---|
| Database | [Neon](https://neon.tech) | 0.5 GB, permanent | Render's own free Postgres is **deleted after 30 days** — every account would vanish with it |
| API | [Render](https://render.com) | 512 MB, 750 h/month | Runs the FastAPI app directly from this repo; `render.yaml` is checked in |
| Frontend | [Vercel](https://vercel.com) or [Cloudflare Pages](https://pages.cloudflare.com) | unlimited static | Static build, no server needed |

The backend fits the free tier because it no longer carries torch, faiss or
sentence-transformers: the install is ~150 MB, and nothing is written to disk at
runtime.

---

## Before you start

You need a [Groq API key](https://console.groq.com/keys) (free) and a GitHub
account with this repository pushed to it.

---

## 1. Database — Neon

1. Create a project at [neon.tech](https://neon.tech).
2. Copy the **connection string**. It looks like:

   ```
   postgresql://user:password@ep-something.region.aws.neon.tech/neondb?sslmode=require
   ```

3. Keep `?sslmode=require` on the end — Neon rejects unencrypted connections.

Nothing else is needed. The API runs `alembic upgrade head` on every boot, so the
schema is created on the first deploy and migrated on later ones.

---

## 2. API — Render

1. Render → **New** → **Blueprint**, and point it at your fork. It reads
   [`render.yaml`](render.yaml) and creates the service.
2. Set the four secret variables in the dashboard (the blueprint marks them
   `sync: false`, so they are never committed):

   | Variable | Value |
   |---|---|
   | `DATABASE_URL` | the Neon string from step 1 |
   | `GROQ_API_KEY` | your Groq key |
   | `CORS_ORIGINS` | leave empty for now — you set it in step 4 |
   | `GITHUB_TOKEN` | optional; raises the GitHub API limit from 60 to 5000 req/h |

3. Deploy. When it finishes, open `https://<your-service>.onrender.com/` — it
   should return `{"message": "AI Career Coach API is running"}`.

`SECRET_KEY` is generated by Render on first deploy and then left alone.
Regenerating it invalidates every issued JWT and signs all users out.

---

## 3. Frontend — Vercel

1. Vercel → **Add New** → **Project**, import the repository.
2. Set **Root Directory** to `frontend`. It picks up
   [`frontend/vercel.json`](frontend/vercel.json) for the build and the
   single-page-app fallback.
3. Add one environment variable:

   | Variable | Value |
   |---|---|
   | `VITE_API_URL` | `https://<your-service>.onrender.com` |

   This is read at **build time**, not run time — after changing it you must
   redeploy, not just restart.

4. Deploy, and note the resulting URL.

<details>
<summary>Cloudflare Pages instead</summary>

Build command `npm run build`, output directory `dist`, root directory
`frontend`, and the same `VITE_API_URL` variable.
[`frontend/public/_redirects`](frontend/public/_redirects) supplies the SPA
fallback there.
</details>

---

## 4. Connect the two

Back in Render, set `CORS_ORIGINS` to the exact frontend URL, with no trailing
slash:

```
CORS_ORIGINS=https://your-app.vercel.app
```

Add any custom domain as a second comma-separated entry. Then redeploy the
service.

If you skip this the app loads but every API call is blocked by the browser, and
the failure surfaces on the login screen as *"invalid credentials"* rather than
as a CORS error.

---

## What to expect on the free tier

**The first request after ~15 minutes of no traffic takes about a minute.**
Render stops idle free services, and the next request has to start the container
and run migrations before it answers. It is not a hang. Paid instances and
Render's cron-style keep-alive both avoid it; so does simply accepting it for a
portfolio deployment.

**Neon suspends an idle database too**, but it wakes on the next connection and
adds only a second or so.

**Uploaded PDFs are not kept.** A resume is parsed on upload and only the
extracted text is stored. This is deliberate: free hosts have ephemeral disks, so
a stored file would disappear on the next restart while the database row went on
pointing at it. Avatars are kept, as bytes in the database, for the same reason.

**750 instance-hours a month** covers one service running continuously.

## Verifying a deploy

```bash
curl https://<your-service>.onrender.com/
```

Then in the browser: register an account, upload a resume, and open the roadmap.
That exercises Postgres, PDF parsing and the Groq API in one pass.

If the AI features fail with *"The AI service is unavailable right now"*, check
the Render logs. The usual cause is a `model_not_found` from Groq — model
availability changes without notice, and `llama-3.3-70b-versatile` was withdrawn
during this project's development. Set `GROQ_MODEL` to a model your account can
currently serve; `openai/gpt-oss-120b` and `openai/gpt-oss-20b` were the working
options at the time of writing.

---

## Self-hosting with Docker instead

`docker compose up --build` runs the whole stack — Postgres, API and an nginx
frontend — on one machine. Copy `.env.docker.example` to `.env` in the repository
root first and fill in `POSTGRES_PASSWORD`, `SECRET_KEY` and `GROQ_API_KEY`.
nginx proxies `/api` from the frontend's own origin, so `CORS_ORIGINS` does not
come into play in that setup.
